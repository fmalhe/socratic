# AGENTS.md

Guidelines for coding agents working on **Socratic** (`io.fmalhe.socratic`).

## Tech Stack
- **Java 25** & **Spring Boot 4.2.0** (Maven Wrapper `./mvnw`, Virtual Threads enabled)
- **Spring Modulith 2.2.0** (strict vertical module boundaries + JDBC event publication)
- **jOOQ (`SQLDialect.SQLITE`)** + **SQLite** + **Flyway** — **NO JPA / Hibernate**
- **Spring AI 2.1.0** (Google Gemini multimodal `ChatClient` with `.entity(...)`)
- **Lombok** (`@RequiredArgsConstructor`), **JSpecify** (`@NullMarked`), **Checkstyle**, **OpenRewrite**, **ArchUnit**

## Build & Verification Commands
Always run with JDK 25:
```bash
# Auto-format, clean imports, and apply OpenRewrite modernization
./mvnw test-compile rewrite:run

# Full verification: Flyway + jOOQ codegen, tests (unit, @WebMvcTest, @ApplicationModuleTest, ArchUnit, Modulith), Checkstyle, and rewrite:dryRun
./mvnw verify
```
`./mvnw verify` fails if any test, Modulith boundary check, ArchUnit rule, Checkstyle rule, or OpenRewrite `dryRun` check fails.

## Module Architecture (Spring Modulith)
Root package: `io.fmalhe.socratic`
- **Domain modules:** `profile`, `reading`, `homework`, `audio`, `progress`
- **Shared/open modules:** `jooq` (`@ApplicationModule(type = OPEN)` — generated by jOOQ Maven plugin) and `config` (`WebCorsConfig`, `ProfileIdArgumentResolver`)
- **SQLite Modulith support:** `io.fmalhe.sqlite.modulith` (outside `io.fmalhe.socratic` so Modulith's `ModuleTypeExcludeFilter` keeps `SqliteEventPublicationAutoConfiguration` active in `@ApplicationModuleTest`)

### Package Layout per Module
- `<module>` (root): **Public API only** — facades (`ProfileFacade`), value objects (`ProfileId`, `LanguageCode`, `Age`, `TtsVoiceName`, `HomeworkQuestion`), DTOs, request/response models, domain events (`ActivityCompletedEvent`).
- `<module>.web`: REST controllers (encapsulated from other modules by Spring Modulith).
- `<module>.internal`: Services, prompt factories, jOOQ repositories (encapsulated from other modules).

Other modules must only depend on another module's root package (verified by `ModulithArchitectureTest`).

## Database & jOOQ Conventions
- **NO JPA / Hibernate.** Use `DSLContext` with generated classes from `io.fmalhe.socratic.jooq.Tables`.
- Schema changes go in `src/main/resources/db/migration/V<N>__<desc>.sql` using SQLite-compatible DDL (`INTEGER PRIMARY KEY AUTOINCREMENT`, `TEXT`, `INTEGER`).
- `./mvnw generate-sources` runs Flyway against `target/jooq-codegen.db` and regenerates jOOQ tables/records into `target/generated-sources/jooq` (excluded from OpenRewrite and Checkstyle).
- Spring Modulith's automatic JDBC schema init is disabled (`spring.modulith.events.jdbc.schema-initialization.enabled=false`); `event_publication` is managed via Flyway and `SqliteEventPublicationRepository`.

## Coding Conventions (Enforced by ArchUnit, Checkstyle & OpenRewrite)
- **Value Objects over Primitives:** Use domain `record` value objects (`ProfileId`, `LanguageCode`, `Age`, `TtsVoiceName`, `HomeworkQuestion`) with `@JsonValue` / `@JsonCreator` instead of raw primitives on API/controller boundaries.
- **No `Optional` on Controllers or Fields:**
  - Never use `Optional` as a field or Java `record` component (`CodingRulesTest`).
  - Never use `Optional` as a `@RestController` method parameter (`CodingRulesTest`).
  - For optional request headers/context (like `X-Profile-Id`), use Spring `HandlerMethodArgumentResolver` (`ProfileIdArgumentResolver` defaults to `ProfileId.DEFAULT`).
  - For types with optional data (`SpeakRequest`, `HomeworkHelpRequest`, `ProgressResponse`), use an immutable class with a private `@Nullable` field and a public `Optional<T>` getter.
  - Never call `Optional.get()` (`CodingRulesTest`); use `orElse`, `orElseGet`, `orElseThrow`, `map`, or `ifPresent`.
- **Lombok & Modern Java:** Use `@RequiredArgsConstructor` for constructor injection, Java `record`s for non-nullable DTOs/value objects, and `var` for obvious local variable types.
- **Imports & Formatting:** No star imports (`*`), no unused/redundant imports (enforced by `checkstyle.xml` and OpenRewrite `io.fmalhe.socratic.NoStarImports`).
- **Dynamic AI Prompting:** Never hardcode languages or dialect rules in prompts, DTOs, or services; always load from `ProfileFacade` and inject `{age}`, `{targetLanguageName}`, `{nativeLanguageName}`, and `{dialectRules}` via Spring AI `PromptTemplate`.
